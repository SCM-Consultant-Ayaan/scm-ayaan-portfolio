# 다법인·다창고 재고수불부

아이리스브라이트·케이빅스·말러(및 향후 추가되는 법인)가 여러 창고·물류사에 나눠
보관하는 재고를 하나의 수불부로 관리하는 독립 툴입니다. 기존 "재고 대시보드"와는
별개의 툴이며, 입고만 [발주내역_관리시트]에서 읽기 전용으로 가져옵니다.

설계 배경과 결정 과정은 별도로 정리한 설계 문서를 참고하세요(대화 중 공유된 아티팩트).

## 구성

```
inventory-ledger/
  apps-script/     Google Apps Script 백엔드 (doGet/doPost 웹앱)
  frontend/        정적 HTML/JS 프론트 (Cloudflare Pages 등에 그대로 배포)
```

## 준비된 것

- 저장소 스프레드시트를 미리 만들어뒀습니다: <https://docs.google.com/spreadsheets/d/1I-dPWe-cHpZM-D6DcqsYnbpIibf2O65HlCZ56IW4Bq0/edit>
  (지금은 빈 파일이고, 아래 1단계에서 구조를 채웁니다.)

## 1. 백엔드 설정 (Apps Script)

1. 위 저장소 스프레드시트를 열고 **확장 프로그램 > Apps Script**로 들어갑니다.
2. `apps-script/` 폴더의 파일 10개(`Config.gs`, `SheetUtil.gs`, `Setup.gs`, `Auth.gs`,
   `Masters.gs`, `SkuMapping.gs`, `PoSync.gs`, `Transactions.gs`, `Ledger.gs`,
   `WebApp.gs`)를 그대로 복사해서 각각 같은 이름의 스크립트 파일로 붙여넣습니다.
   (`clasp`을 쓴다면 `clasp push`로 한 번에 올려도 됩니다. `appsscript.json`도 함께 반영됩니다.)
3. 함수 선택 드롭다운에서 **setupAll**을 고르고 ▶ 실행합니다. 처음 실행 시 권한 승인
   화면이 뜨면 승인해주세요. 실행이 끝나면 모든 탭·헤더·기본 마스터 데이터가 생성됩니다.
4. 스프레드시트로 돌아가 **[연동설정]** 탭에서 다음 값을 채웁니다.
   - `PO_SSID`: [발주내역_관리시트]의 스프레드시트 ID (URL의 `/d/` 뒤 문자열)
   - `SKU_SSID`: SKU 매핑 시트의 스프레드시트 ID
   - 나머지 `PO_COL_*` / `SKU_COL_*` 값은 기본값이 이미 채워져 있습니다. 원본 시트의
     헤더 이름이 다르면 이 값만 바꾸면 됩니다(코드 수정 불필요).
5. **[법인마스터]** 탭에서 실제 법인 정보를 확인/수정합니다. 해외법인은 국내외구분을
   "해외"로, 통화코드를 그 나라 통화로 지정하세요. 국내법인은 항상 KRW로 고정됩니다.
6. **[환율마스터]** 탭의 예시 환율을 실제 값으로 갱신합니다.
7. 스프레드시트 메뉴 **[재고수불부 > 관리자 비밀번호 설정]**으로 비밀번호를 설정합니다.
8. Apps Script 편집기에서 **배포 > 새 배포**를 선택하고, 유형은 "웹 앱", 실행 계정은
   "나", 액세스 권한은 "모든 사용자"로 배포합니다. 배포 후 나오는 웹 앱 URL을 복사해둡니다.

## 2. 프론트엔드 배포

`frontend/index.html` 한 파일만 있으면 됩니다. Cloudflare Pages(또는 아무 정적 호스팅)에
그대로 올립니다.

1. 배포된 페이지를 열고 **설정** 탭으로 이동합니다.
2. "Apps Script 웹앱 URL"에 1단계 8번에서 복사한 URL을 붙여넣고 저장합니다. 이 값은
   브라우저(localStorage)에만 저장되므로 파일을 다시 빌드/배포할 필요가 없습니다.
3. 우측 상단 **관리자 로그인**으로 비밀번호를 입력하면 입력·수정 화면이 열립니다.

## 데이터 모델 요약

- **거래유형 7가지**: 입고(구매입고 자동 + 무상입고/반품입고 수동) · 출고(판매출고/기타출고)
  · 폐기 · 기부 · 사간거래 · 창고간이동 · 재고조정(재고실사/재고전환/전산재고조정)
- **입고 입력 화면**은 성격(구매입고/무상입고/반품입고/창고이동입고/사간거래입고)을 고르면
  실제로는 알맞은 탭(`거래_입고`/`거래_창고이동`/`거래_사간거래`)에 자동으로 기록됩니다.
- **사간거래**·**창고간이동**은 1건만 입력하면 출발/도착 양쪽에 계산 시점에 자동으로
  반영됩니다 — 반대편에 별도로 입력할 필요가 없습니다.
- **이동평균단가**는 (법인, 창고, SKU) 조합별로 계산되고, 매입수량·사간거래IN·창고이동IN만
  단가 계산에 영향을 줍니다(무상입고/반품입고/재고조정은 수량만 바뀌고 단가는 유지).
- **통화**는 창고가 아니라 소유법인에 귀속됩니다. 국내법인 소유는 항상 KRW, 해외법인
  소유는 그 나라 통화로 계산되고, 사간거래로 통화가 바뀌는 시점에는 환율마스터로 환산됩니다.

## 알려진 가정 · 제약사항

- 발주내역_관리시트의 "입고내역" 탭에서 `마감여부 = "마감"`인 행만 가져옵니다. 검수결과가
  아직 입력되지 않은 분할입고 행은 다음 조회 때 자동으로 포함됩니다.
- 입고내역에 KRW가 아닌 통화로 기록된 발주 건은 이동평균단가 계산에서 제외되고, 대시보드
  상단 경고에 표시됩니다 — 수동으로 확인 후 처리해주세요.
- SKU 매핑 시트의 소유법인 값이 법인마스터의 법인명과 정확히 일치하지 않으면 그 SKU는
  법인 미매핑으로 표시되고 수불부 계산에서 빠집니다(조용히 누락되지 않고 경고로 표시됩니다).
- 사간거래·창고이동의 원가 승계는 "전월 말 이동평균단가"를 기준으로 합니다(같은 달 순환
  참조를 피하기 위한 설계). 같은 달에 A→B→C로 연쇄 이동하는 경우 C는 B의 "전월" 단가를
  받게 되어 약간의 근사가 생길 수 있습니다.
